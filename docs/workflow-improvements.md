# Улучшения пользовательских сценариев

## Что изменилось

- Предпросмотр заголовка RINEX, включая gzip, в браузере до отправки. Читается не более 256 КиБ распакованных данных. Показываются дата, длительность (если указаны обе границы), антенна и диапазоны. Это не полная проверка качества наблюдений. Для PPP есть предупреждения о недостатке фазовых частот и свежих наблюдениях.
- Выбор устройства из профиля. Параметры приёмника применяются только при явном выборе профиля (`antennaSource=profile`); иначе сохраняется чтение из RINEX. Просроченные параметры не подставляются. Параметры должны быть в ENU: результаты калибровки в осях корпуса автоматически в ENU не преобразуются.
- Текущий этап выполняющейся задачи возвращается в API статуса. Этапы хранятся только в памяти процесса и удаляются по завершении; после перезапуска остаётся общий статус из существующей БД. Для нескольких экземпляров сервиса этап доступен на экземпляре, выполняющем задачу.
- После временных ошибок опрос статуса продолжается; HTTP-ошибка не означает исчезновение задачи. Статус задачи доступен только владельцу.
- Фильтры имени файла, метода, статуса и дат; страницы по 50 записей. Даты фильтруются в часовом поясе БД. Условия доступности и сроки хранения не изменены.
- Копирование координат, пояснения к качеству решения, сравнение двух результатов в открытой вкладке. Повтор передаёт настройки в новую вкладку через same-origin postMessage, без сохранения дополнительной истории. Исходный файл выбирается заново.
- Подключения и диагностика доступны из профиля. Страницы больше не перенаправляют безусловно на главную. Запуск серверного позиционирования по-прежнему выключен в `Application.Run`. Попытка включить расчёт при отключённом воркере возвращает 503, интерфейс объясняет причину.
- Диагностика различает доступность воркера, состояние процесса и свежесть решения. Отдельной телеметрии входного потока и поправок в текущем протоколе нет — отображается «нет телеметрии», а не ложный статус подключения. Время решения обновляется по изменению файла, а не на каждом чтении одного результата.

## Хранение

Новых таблиц, журналов активности, продления TTL или повторного хранения скачанных файлов нет. Удаление файла после скачивания и существующая очистка остаются. Административной страницы нет.

## Проверка и установка

```sh
go test ./...
node --test static/js/workflow.test.cjs
```

Интеграционные тесты PostgreSQL запускаются с `TEST_DATABASE_DSN` и создают отдельные временные схемы, удаляемые после тестов. Используйте отдельную тестовую базу.

Для установки нужно собрать `go build -o server.new ./cmd/server`, перенести бинарник и изменённые файлы каталога `static` и перезапустить сервис штатным способом. Миграций для этих улучшений нет. Старый бинарник в репозитории автоматически не обновляется. На удалённый сервер изменения из этой задачи не устанавливались.
